# Nia

Nia is a public-safe operational knowledge base for leading a large, multi-person service site.

It is designed to be readable from an internal generative-AI environment through public GitHub URLs while keeping confidential operational context outside this repository.

## What this repository contains

- [INITIATIVES.md](INITIATIVES.md) — initiatives completed, underway, and being designed
- [TASKS.md](TASKS.md) — current priorities expressed as observable actions
- [OPERATING_MODEL.md](OPERATING_MODEL.md) — decision priorities, roles, review cadence, and data rules
- [MINERVA_GUIDE.md](MINERVA_GUIDE.md) — safe prompts and URLs for reading these files from an internal AI tool

## Current focus

1. Maintain leadership continuity during role changes.
2. Strengthen safety, escalation, and independent review.
3. Connect patient value indicators with operational productivity.
4. Analyze service flow using correctly separated time definitions.
5. Delegate routine decisions and develop frontline capability.
6. Build reusable research, education, and AI-assisted knowledge workflows.

## Information boundary

This is a **public repository**. It is not the private source of truth.

Never store:

- real names, initials tied to people, employer or site names;
- patient information, case histories, prescription details, or contact information;
- exact staffing, workload, financial, KPI, or incident figures;
- exact transfer dates, schedules, facility names, or internal organization charts;
- internal system names, internal URLs, authentication details, or network structure;
- private correspondence, meeting transcripts, or unpublished research data.

When sensitive context is required, keep only a neutral task code here. Store the detailed source material in an approved non-public location.

## Update rule

Every active item should have:

- one purpose;
- one next observable action;
- one completion condition;
- a status that is updated instead of adding endless proposals.

Completed work is summarized in [INITIATIVES.md](INITIATIVES.md); active execution remains in [TASKS.md](TASKS.md).
