# Active Task List

> Public-safe execution list. Sensitive details belong only in an approved non-public location.

## Status legend

- `[ ]` not completed
- `[x]` completed
- `P0` safety, deadline, legal, or continuity risk
- `P1` patient value, operational performance, or critical development
- `P2` system improvement, research, or reusable knowledge

## P0 — Stabilize responsibility and risk controls

- [ ] **G-01a** — Create a role-level decision map for routine, delegated, leadership, and formal-authority work.  
  **Done when:** every critical category has an owner role, backup role, and escalation condition.

- [ ] **G-03a** — Split transition work into operational, compliance, open-case, communication, and access/asset handoffs.  
  **Done when:** each stream has evidence of transfer and a closure check.

- [ ] **S-01a** — List high-risk workflows and mark where approval, execution, and review must be separated.  
  **Done when:** no listed workflow has an unreviewed single-person path.

- [ ] **S-03a** — Confirm organizational boundaries for exceptional or personalized service requests.  
  **Done when:** approved service, prohibited service, documentation, handoff, and escalation routes are explicit.

## Weekly review template

1. What materially changed?
2. Which P0 item remains open, and why?
3. Which single bottleneck is controllable this week?
4. What can be delegated?
5. Which task should be closed instead of carried forward?
6. What sensitive detail must remain outside this repository?

## Repository safety rule

Do not add real names, employer/site/facility names, patient or prescription information, internal system names, private URLs, credentials, exact schedules, or confidential figures. Use the task code here and keep sensitive details in an approved non-public source.
